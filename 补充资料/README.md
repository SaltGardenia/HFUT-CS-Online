# 本站补充资料

本目录是本项目自有的资料仓库，用来存放 4 个上游资料仓库没有覆盖到的课程资料（新课课件、近年试卷、实验材料等），作为 `data/` 的补充。

## 与 `data/` 的区别

| | `data/` | `补充资料/`（本目录） |
| --- | --- | --- |
| 来源 | 4 个上游 HFUT 资料仓库的整理产物 | 本站自行收集 / 同学投稿 |
| 是否入库 | 不入库（仅本地，`.gitignore` 已忽略） | **入库**，随本仓库分发 |
| 附件页下载 | 跳转上游仓库 raw 直链 | 本仓库 raw 直链，`git mv` 搬动不丢溯源 |

两者目录契约完全相同，`scripts/build-catalog.mjs` 会把它们按同一门课合并后生成 `catalog.ts` 与附件清单。同一份文件**只需放一处**：上游仓库已有的放 `data/`，没有的放这里。

## 目录契约

```
补充资料/
└── <学期>/<课程>/{课件,试题,附件}/…
```

- `<学期>`：`大一上`、`大一下`、`大二上`、`大二下`、`大三上`、`大三下`、`大四上`、`大四下`，与 `data/` 一致。
- `<课程>`：课程名必须与 `data/` 中同名课程的目录名**完全一致**（如 `计算机网络`），否则会被当成另一门课，在首页/课程页多出一条目录。
- 三个类别目录的判定规则见 `data/整理说明.md`：`课件`、`试题`、`附件`。
- 课程内部可以继续建子目录（如 `课件/2025/`），附件页会按原样展示。

## 新增资料的步骤

1. 按上面的契约把文件放进对应目录（新建课程时同时建好课程目录）。
2. 运行 `npm run catalog:supplement`，它会重建 `src/content/catalog.ts` 与 `public/attachments/*.json`（不需要本地 `data/`；CI 会校验生成物是否最新）。
3. 连同生成物一起提交。附件页会从本仓库 raw 直链下载，并显示文件的上传者（取自 git 首次提交该作者）。

## 命名与冲突

- 文件名保持原样，不要为了排序加序号；目录内按中文序展示。
- 与 `data/` 中同名同路径的文件冲突时，本目录的一份保留并在文件名后加 `（本站补充）` 后缀，两份都会出现在附件页。
- 体积较大的 PDF / PPT 直接入库会增加克隆体积，超过约 50MB 的单文件建议先压缩再放。
